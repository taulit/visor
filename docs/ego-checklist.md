# Review checklist for extensions.gnome.org

Visor checked against the [review guidelines](https://gjs.guide/extensions/review-guidelines/review-guidelines.html) of extensions.gnome.org. The guidelines were **read from the web** (gjs.guide, 2026-11-17) and this file follows their order. The code is the state of this branch, `file:line` refers to it.

Status: **ok** (checked, nothing to do), **violation** (the code breaks the rule as written), **maintainer** (a decision or an action that only the maintainer can take).

Not tested here: GNOME Shell 51 (verified.md covers 50.5 only) and the review itself. Nothing in this file replaces a read-through of the code by the person who submits it, see the end.

## Read these first

If you can explain only a few files before you submit, make them these five. They are the ones that cost most to explain, from a simplicity review of the V4 branch. Counts and line numbers are from this branch; they drift.

| File                            | Why it is hard                                                                                                                                                                                                                                                       |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/core/kit.ts`               | One row object keeps about 25 nullable widgets (26 fields typed as nullable at the time of writing), each built the first time a row needs it. To know which ones exist for a row you have to read how rows are updated, not the field list.                         |
| `src/core/notch.ts`             | Relies on shell internals (`_centerBox`, `_bannerBlocked`, `_delegate` of the menu root: see "Private or undocumented shell API" below) and on per-frame geometry: the content has its final size at once and only its clip rectangle grows (header comment, `:15`). |
| `src/core/search/controller.ts` | Generations (`generation`, `:76`), a cancellable and an idle source (`:90`, `:195`) are interleaved; a late answer is dropped by comparing the generation (`:266`). The order in which these are reset when the query changes is the part to understand.             |

## Before submitting

Things only the maintainer can do. None of them has been done.

1. **Read the code and be able to explain it.** The store rejects code that looks machine-written and asks the author to justify it ("Extensions must not be AI-generated"). Read every file under `src/`, starting with `src/extension.ts`, `src/core/notch.ts`, `src/core/registry.ts`, `src/core/keybindings.ts` and the modules, until you can say why each part exists. Remove what you cannot explain. `kit.ts`, `notch.ts` and `sheet.ts` are the largest (docs/handoff.md).
2. Be able to explain the one `run_dispose()` that is left (`closeSession()` in `src/modules/upcoming/links.ts`).
3. Run Visor in your own session on GNOME Shell 50, and on 51 or take 51 out of `shell-version`. Everything so far ran in the sandbox.
4. Make the repository public, so `url` in `metadata.json` works (release-checklist.md).
5. Check that the name "Visor" is free in the store and that the description in `metadata.json` says what you want it to say about the clipboard and the network.
6. Upload `dist/visor@taulit.github.io.shell-extension.zip` from a clean `pnpm install && pnpm pack:zip`, and answer the reviewers with the notes of this file.
